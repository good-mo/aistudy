## 一、系统概述

本项目是一个 **自动化测试用例生成与测试管理平台**，融合了两大核心能力：

1. **AI 驱动的测试用例生成** — 基于 LangGraph 工作流，自动分析源代码并生成可运行的 pytest 测试。
2. **企业级测试管理** — 集成了 MeterSphere v3.x 前端，提供用例管理、接口测试、缺陷跟踪、报告中心等完整测试工作流。

### 核心架构

```
┌────────────────────────────────────────────────┐
│         Web 控制台（FastAPI + Vue3）            │
│  ├─ MeterSphere 前端（/ms）                    │
│  ├─ 精简控制台（/）                            │
│  └─ REST API + WebSocket                       │
├────────────────────────────────────────────────┤
│            LangGraph 工作流                     │
│  scan_code → generate_mocks → generate_tests   │
│    → test_runner ⇄ refinement → coverage       │
│    → performance_test                          │
├────────────────────────────────────────────────┤
│           服务支撑层                            │
│  ├─ Docker 沙箱（安全隔离测试执行）             │
│  ├─ 异步任务队列                                │
│  ├─ SQLite 持久化（tga.db）                    │
│  └─ LLM Provider（OpenAI/Azure/本地）          │
└────────────────────────────────────────────────┘
```

### 支持的测试类型（7 种）

| 类型 | key | 说明 |
|------|-----|------|
| 功能测试 | `functional` | 验证业务功能正确性 |
| 接口测试 | `api` | 验证 API 请求/响应契约 |
| UI 测试 | `ui` | 验证用户界面元素与交互 |
| 性能测试 | `performance` | 验证响应时间、吞吐量与 SLO |
| 安全测试 | `security` | 验证注入、越权与敏感信息保护 |
| 兼容性测试 | `compatibility` | 跨版本/跨平台/跨配置兼容 |
| 可靠性测试 | `reliability` | 幂等性、容错性与稳定性 |

## 三、安装部署

### 3.1 从源码运行（开发环境）

#### 步骤 1：克隆代码

```bash
git clone <仓库地址> test-gen-agent
cd test-gen-agent
```

#### 步骤 2：安装后端依赖

```bash
pip install -r requirements.txt
```

#### 步骤 3：配置环境变量

```bash
cp .env.example .env
# 编辑 .env，填入 OPENAI_API_KEY（详见第四章）
```

#### 步骤 4：启动服务

```bash
# 方式一：直接使用 uvicorn
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# 方式二：使用开发脚本（推荐）
./scripts/dev-frontend.sh            # 同时启动前后端
./scripts/dev-frontend.sh backend    # 仅启动后端
./scripts/dev-frontend.sh frontend   # 仅启动前端
```

启动后访问：
- 精简控制台：`http://localhost:8000`
- MeterSphere 前端：`http://localhost:5173`（开发模式）
- API 文档：`http://localhost:8000/docs`

### 3.2 Docker Compose 部署（前后端调试）

```bash
# 1. 配置环境变量
cp .env.example .env

# 2. 构建并启动
docker compose up --build -d

# 3. 查看日志
docker compose logs -f

# 4. 停止
docker compose down
```

访问地址：
- 前端（Vite dev server + HMR）：`http://localhost:5173`
- 后端（FastAPI 文档）：`http://localhost:8000/docs`

### 3.3 Docker 单容器部署

```bash
# 构建镜像（包含前端构建产物 + 后端运行时）
docker build -t test-gen-agent .

# 运行
docker run -p 8000:8000 \
  -e OPENAI_API_KEY=your-key \
  -v $(pwd)/data:/app/data \
  test-gen-agent
```

访问：
- 精简控制台：`http://localhost:8000`
- MeterSphere 前端：`http://localhost:8000/ms`

## 四、配置说明

所有配置通过 `.env` 文件管理（复制自 `.env.example`）。配置使用 Pydantic Settings 自动加载并做类型校验。

### 4.1 LLM Provider 配置

```ini
# 可选: openai | azure | local（OpenAI 兼容端点）
LLM_PROVIDER=openai
LLM_MODEL=gpt-4o
LLM_TEMPERATURE=0.0
LLM_TIMEOUT=120
LLM_MAX_RETRIES=2

# OpenAI / OpenAI 兼容端点（必填）
OPENAI_API_KEY=sk-your-actual-key-here
# 可选：自定义 base_url（本地或兼容端点时配置）
# OPENAI_API_BASE=https://your-endpoint/api/v1
```

**支持三种 Provider：**

1. **OpenAI**：默认，直接使用 `OPENAI_API_KEY`
2. **Azure OpenAI**：配置 `AZURE_API_KEY`、`AZURE_ENDPOINT`、`AZURE_API_VERSION`
3. **本地兼容端点**（vLLM/Ollama/LiteLLM）：配置 `OPENAI_API_BASE` 指向本地端点，`OPENAI_API_KEY` 可填任意占位符

### 4.2 Agent 行为配置

```ini
MAX_RETRIES=3              # 测试修复最大重试次数
MAX_COVERAGE_RETRIES=5     # 覆盖率补测总重试上限
COVERAGE_THRESHOLD=80.0    # 覆盖率达标阈值(%)
TEST_TIMEOUT=60            # 单次 pytest 运行超时（秒）
```

### 4.3 服务配置

```ini
HOST=0.0.0.0               # 监听地址
PORT=8000                  # 监听端口
ENVIRONMENT=development    # development/staging/production
DEBUG=true                 # 生产环境建议 false
```

### 4.4 Docker 沙箱配置

```ini
SANDBOX_ENABLED=true       # 是否启用 Docker 沙箱隔离
SANDBOX_IMAGE=python:3.12-slim
SANDBOX_MEM_LIMIT=512m     # 容器内存限制
SANDBOX_NANO_CPUS=1000000000  # CPU 限制（1 CPU = 1e9）
SANDBOX_NETWORK_MODE=none  # 默认禁用网络（安全）
```

> **注意**：在本地调试（docker-compose）时建议设置 `SANDBOX_ENABLED=false`，避免 Docker-in-Docker 嵌套。

### 4.5 性能测试配置

```ini
PERF_ENABLED=false          # 是否在用例生成流程中默认执行性能测试
PERF_ITERATIONS=50          # 采样次数
PERF_WARMUP=5               # 预热次数
PERF_CONCURRENCY=1          # 并发线程数
PERF_P95_MAX_SEC=1.0        # P95 响应时间上限（秒）
PERF_THROUGHPUT_MIN=10.0    # 吞吐量下限（次/秒）
PERF_MEMORY_MAX_MB=512.0    # 峰值内存上限（MB）
```

### 4.6 LLM 限流重试

```ini
LLM_RATE_LIMIT_MAX_RETRIES=3      # 限流错误最大重试次数
LLM_RATE_LIMIT_BASE_DELAY=2.0     # 初始等待秒数
LLM_RATE_LIMIT_MAX_DELAY=30.0     # 最大等待秒数
LLM_RATE_LIMIT_BACKOFF_FACTOR=2.0 # 退避倍数
```

## 五、快速上手

```bash
# 生成默认功能测试
python -m app.cli generate --source-file examples/wechat_upload.py

# 指定测试类型生成
python -m app.cli generate --source-file examples/wechat_upload.py --test-type api
python -m app.cli generate --source-file examples/wechat_upload.py --test-type security
python -m app.cli generate --source-file examples/wechat_upload.py --test-type performance
```

## 八、核心功能详解

### 8.1 AI 测试生成工作流

系统使用 LangGraph 状态图驱动整个生成流程：

```
START
  → scan_code          (AST 提取函数签名)
  → generate_mocks     (规则驱动生成 Mock 配置)
  → generate_tests     (LLM 生成 pytest 测试)
  → test_runner        (子进程沙箱运行测试)
      ⇄ refinement     (失败时定向修复，条件重试)
  → coverage_analysis  (覆盖率差距分析)
      ⇄ refinement     (覆盖率不达标时可补测)
  → performance_test   (性能基准 + SLO 校验，可选)
  → END
```

**智能重试机制：**
- 测试失败时自动进入修复循环（最多 `MAX_RETRIES` 次）
- 覆盖率不达标时触发补测（最多 `MAX_COVERAGE_RETRIES` 次）
- 不可恢复的致命错误会跳过修复直接进入覆盖率分析

### 8.2 用例库管理

**用例状态流转：**
```
草稿(draft) → 评审中(review) → 已批准(approved) / 已废弃(deprecated)
```

**核心操作（Web 控制台）：**

| 操作 | 说明 |
|------|------|
| 创建用例 | 填写标题、描述、标签、优先级、测试类型 |
| 搜索过滤 | 按状态/优先级/标签/关键词过滤 |
| 脑图视图 | 树形结构展示用例层级 |
| 导入/导出 | Excel(CSV) / XMind(JSON) 格式 |
| 评审流程 | 提交评审 → 通过/驳回 |
| 依赖关系 | 前置/后置依赖管理 |
| 回收站 | 软删除 → 恢复/彻底删除 |
| 版本管理 | 自动快照、版本回滚 |
| 变更记录 | 完整审计日志 |
| 需求关联 | 关联 JIRA/TAPD 需求工单 |

### 8.3 缺陷跟踪

**缺陷严重程度：**
- `Blocker`（🔴 阻塞级）
- `Critical`（⛔ 严重）
- `Major`（🟠 主要）
- `Minor`（🟡 次要）

**状态流转：**
```
打开(open) → 进行中(in_progress) → 已修复(fixed) → 已关闭(closed) / 不修复(wont_fix)
```

### 8.4 项目管理

- 项目 CRUD：创建/查看/更新/删除
- 语言标注：Python/Java/JavaScript/Go
- 项目状态：active/archived

### 8.5 测试洞察（一线测试人员功能）

| 功能 | API | 说明 |
|------|-----|------|
| 价值量化 | `GET /api/insights/value` | 缺陷价值分、覆盖率可视化、避免事故估算 |
| 执行追溯 | `GET/POST /api/insights/trace` | 每次测试留痕、一键"自证清白" |
| 风险预警 | `GET /api/insights/risk` | 代码复杂度+覆盖率缺口+缺陷密度风险分 |
| 低代码生成 | `POST /api/insights/lowcode` | 自然语言描述 → 自动生成 pytest |
| 技能阶梯 | `GET /api/insights/skill-path` | 功能→自动化→测试开发职业进阶 |

## 九、接口测试模块

### 9.1 功能概览

集成 MeterSphere 风格的接口测试能力：

| 功能 | 说明 |
|------|------|
| 接口定义管理 | HTTP/TCP/SQL/DUBBO 协议 |
| 接口用例管理 | 断言/前置后置脚本/变量提取 |
| 场景编排 | 多接口按序执行，支持逻辑控制器 |
| Mock 服务 | 模拟接口响应，支持延迟与自定义 |
| 断言规则 | 文本/正则/JSONPath/XPath/状态码 |
| 接口导入 | Postman Collection / Swagger |
| 环境管理 | 多环境切换（Base URL/头/变量） |
| 接口调试 | 在线调试，查看响应与提取变量 |

### 9.2 核心 API

| 功能 | API |
|------|-----|
| 接口定义 CRUD | `GET/POST /api/apitest/definitions` |
| 接口用例 CRUD | `GET/POST /api/apitest/cases` |
| 场景编排 | `POST /api/apitest/scenarios/{id}/execute` |
| Mock 服务 | `GET/POST /api/apitest/mocks` |
| 接口导入 | `POST /api/apitest/import` |
| 环境管理 | `GET/POST /api/apitest/environments` |
| 接口调试 | `POST /api/apitest/debug` |

### 9.3 使用示例（curl）

```bash
# 创建接口定义
curl -X POST http://localhost:8000/api/apitest/definitions \
  -H "Content-Type: application/json" \
  -d '{
    "name": "获取用户信息",
    "method": "GET",
    "path": "/api/users/{id}",
    "protocol": "HTTP"
  }'

# 创建接口用例
curl -X POST http://localhost:8000/api/apitest/cases \
  -H "Content-Type: application/json" \
  -d '{
    "name": "正常获取用户",
    "definition_id": "<definition_id>",
    "assertions": [{"type": "status_code", "expected": 200}]
  }'

# 执行接口调试
curl -X POST http://localhost:8000/api/apitest/debug \
  -H "Content-Type: application/json" \
  -d '{"method": "GET", "url": "https://api.example.com/users/1"}'
```

## 十四、Docker 沙箱隔离

### 14.1 工作原理

测试代码在隔离的 Docker 容器中运行：
- 文件系统隔离
- 网络禁用（默认）
- CPU/内存资源限制
- 自动清理临时容器

### 14.2 配置

```ini
SANDBOX_ENABLED=true
SANDBOX_IMAGE=python:3.12-slim
SANDBOX_MEM_LIMIT=512m

SANDBOX_NETWORK_MODE=none
```

### 14.3 降级行为

当 Docker 不可用时（未安装/无权限），系统自动降级为**宿主机子进程执行**，不影响功能使用。

## 十九、常见问题排查（FAQ）

### Q1: 启动时提示 `OPENAI_API_KEY 未设置`

```
配置校验失败:
  - OPENAI_API_KEY 未设置
```

**解决：** 复制 `.env.example` 为 `.env` 并填入 `OPENAI_API_KEY`。使用本地兼容端点（如 vLLM）可填占位符。

### Q2: 测试生成失败，提示 LLM 限流

**解决：** 系统已内置限流重试机制。检查 `LLM_RATE_LIMIT_*` 配置，适当增加重试次数或调整延迟。

### Q3: Docker 沙箱无法使用

**解决：** 检查 Docker 服务是否启动。未安装 Docker 时系统会自动降级为宿主机执行，不影响基本功能。

### Q4: 前端 `npm install` 报 peer 冲突

**解决：** 必须使用 `--legacy-peer-deps` 参数：
```bash
npm install --legacy-peer-deps --no-audit --no-fund
```

### Q5: 端口被占用

```bash
# 修改端口
PORT=8001 uvicorn app.main:app --host 0.0.0.0 --port 8001
```

### Q6: 数据库文件位置

所有业务数据统一存储在项目根目录的 `tga.db`，LangGraph 检查点存储在 `checkpoints.db`。

### Q7: 前端 API 请求 404

确认访问路径带 `/front/` 前缀（Vite dev 已配置代理）或 `/ms/` 前缀（生产部署）。

### Q8: 生成测试覆盖率不达标

**解决：** 增大 `MAX_COVERAGE_RETRIES`（默认 5）或降低 `COVERAGE_THRESHOLD`（默认 80.0）。

### Q9: 性能测试未触发

确认 `PERF_ENABLED=true`，且测试通过 + 覆盖率达标。

### Q10: WebSocket 无法连接

确保访问路径使用 `/ws/generate`，且在 Nginx 中配置了 WebSocket 升级头。
